# Chapter 27: Scenario Analysis

---

## 27.1 What Is Scenario Analysis

Scenario analysis is a structured method to:
- Explore how risks could materialize
- Understand cause–effect chains
- Assess impact under different conditions

It answers:
“What if this actually happens?”

---

## 27.2 Why Scenario Analysis Is Important

Scenario analysis helps organizations:
- Move beyond static risk registers
- Prepare for uncertainty
- Test decision robustness
- Identify hidden vulnerabilities

It converts abstract risks into concrete stories.

---

## 27.3 Scenarios vs Incidents

| Aspect | Scenario | Incident |
|-----|--------|---------|
| Timing | Future-focused | Past-focused |
| Purpose | Preparedness | Learning |
| Nature | Hypothetical | Real |

Strong risk programs use both.

---

## 27.4 Types of Scenarios

Common scenario types:
- Best-case
- Expected-case
- Worst-case
- Extreme but plausible
- Reverse stress scenarios

Not all scenarios are equal.

---

## 27.5 When to Use Scenario Analysis

Scenario analysis is useful when:
- Data is limited
- Risks are complex
- Dependencies exist
- High-impact outcomes are possible

It complements quantitative models.

---

## 27.6 Scenario Design Principles

Good scenarios are:
- Plausible
- Relevant
- Specific
- Internally consistent
- Decision-focused

Fantasy scenarios add no value.

---

## 27.7 Scenario Structure

Each scenario should define:
- Trigger event
- Risk drivers
- Escalation path
- Control failures
- Consequences

This structure enables repeatability.

---

## 27.8 Identifying Triggers

Triggers are events that initiate risk:
- System failures
- Policy violations
- External shocks
- Human error

Clear triggers prevent vague scenarios.

---

## 27.9 Mapping Risk Propagation

Scenarios must show:
- How one failure leads to another
- Where controls intervene
- Where gaps exist

This reveals systemic weaknesses.

---

## 27.10 Impact Dimensions

Impacts should be assessed across:
- Financial
- Operational
- Legal
- Reputational
- Customer trust
- Regulatory exposure

Single-dimensional analysis is incomplete.

---

## 27.11 Control Stress Testing

Scenario analysis tests:
- Control adequacy
- Detection speed
- Response effectiveness

Controls that fail silently are dangerous.

---

## 27.12 Scenario Severity Rating

Scenarios are rated using:
- Likelihood (qualitative or quantitative)
- Impact severity
- Speed of onset

This supports prioritization.

---

## 27.13 Scenario Documentation

Scenario documentation should include:
- Narrative description
- Assumptions
- Dependencies
- Outcomes
- Mitigation options

Documentation supports governance review.

---

## 27.14 Using Scenarios in Decision-Making

Scenarios inform:
- Investment decisions
- Control enhancements
- Resource allocation
- Policy changes

They support strategic thinking.

---

## 27.15 Scenario Workshops

Workshops improve scenario quality by:
- Including diverse roles
- Challenging assumptions
- Surfacing blind spots

Facilitation matters.

---

## 27.16 Common Scenario Pitfalls

Avoid:
- Overly generic scenarios
- Ignoring interdependencies
- Unrealistic assumptions
- No follow-up actions

Scenarios without action are wasted effort.

---

## 27.17 Scenario Analysis vs Stress Testing

| Scenario Analysis | Stress Testing |
|-----------------|---------------|
| Narrative-based | Quantitative |
| Exploratory | Limit-testing |
| Flexible | Structured |

Both are complementary.

---

## 27.18 Summary

Scenario analysis:
- Makes risks tangible
- Exposes hidden failures
- Improves preparedness
- Strengthens resilience

It is a cornerstone of mature risk management.
